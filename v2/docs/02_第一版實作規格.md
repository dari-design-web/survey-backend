## 二、傳輸協定

- **一般請求**：`POST <exec>`
  - Content-Type 為 `text/plain`，內容為 `{"method":"GET|POST|PUT|DELETE","path":"/api/...?...","body":{},"token":"...","ctoken":"..."}`
  - `token` 為後台管理者憑證；`ctoken` 為客人 Google 登入憑證（存在瀏覽器 localStorage `survey_ctoken`，30 天）。
  - 回應為 `{"status":200,"body":{...}}`。HTTP 狀態碼一律是 200，實際狀態看 `status` 欄位。
- **下載**：`GET <exec>?path=/api/admin/export/...&token=...`，直接回傳 CSV 檔。
- **前端行為**：
  - `status` 為 401 時清除 token 並導向登入頁；≥ 400 時拋出錯誤訊息。
  - `status` 為 503（鎖忙碌）時，等候後自動重試 2 次。
  - 網路錯誤只對 GET 與帶去重編號的送出自動重試。

其他規則：
- 時間以 ISO UTC 儲存，畫面上以台灣時間顯示。
- 以 `=`、`+`、`@` 開頭的文字，儲存時會加上 `'` 避免被當成公式，讀取時自動去除。
- **請勿手動修改** `coupons`、`stock_logs`、`gifts` 的數字欄位。需要調整庫存時，請在後台「贈品庫存」頁操作。

## 五、券號與資格

- **券號格式**：`前綴-YYYYMMDD-流水號-4碼亂數`。日期以台灣時間計算；流水號依前綴、依日分開計數。
- **身分**：啟用 Google 登入（後台設定用戶端 ID）時以 Google 帳號識別；未啟用時以裝置識別碼識別。
- **資格**（跨所有問卷，依帳號判斷）：
  1. 已有尚未過期、尚未使用的券 → 回傳那張券（`existing_coupon`）。
  2. 本自然月（台灣時間）已核銷過任一張券 → 拒絕發券（`monthly_limit`），下月 1 日起可再領。逾期或作廢的券不算。
  3. 以上皆否，再檢查庫存：可發 < 1 → `out_of_stock`。
- **預檢**（precheck）在所有情況都回傳 `login_required`、`need_login`；前台在需登入且未登入時先顯示 Google 登入，不顯示題目。
- **答案一律先保存**：無論最後是否發券，填答內容都會保存。
- **限制**：Google 模式是「每個帳號」，不保證一人一份（一人可有多個 Google 帳號）。裝置模式下清除瀏覽器資料即可繞過。
- **兌換期限**：發券後 24 小時（後台可改小時數），逾時自動取消並回補庫存。

## 六、安全

- **Apps Script 執行設定**：以擁有者身分執行，任何人可存取。權限一律在後端以 token 驗證，不信任前端傳來的角色。
- **Token**：HS256，有效 8 小時。密鑰存在 Script Properties，第一次使用時自動產生。每次請求都會重新核對帳號是否啟用、角色是否一致。
- **密碼**：加鹽 SHA-256 迭代 300 次，至少 8 個字元。登入錯誤 5 次鎖定 10 分鐘。
- **staff**：只能查券與核銷。
- **客人 Google 登入**：前台以 Google Identity Services 取得 ID token，後端向 Google tokeninfo 驗證 aud、iss、exp、sub，並要求 `email_verified` 為 true；發 30 天客人憑證（角色 customer，不能存取後台）。
- **贈品圖片**：瀏覽器自動置中裁成 480×480 正方形、壓縮成 JPEG（≤120,000 字元）；後端檢查格式白名單與實際檔頭（JPEG／PNG／WebP）。更新時先寫新版、切換後才清舊版，中途失敗保留舊圖。
- **QR Code**：在客人瀏覽器以 qrcode-generator 本機產生，券號不傳給第三方。
- **存取權**：試算表只有擁有者能開啟；請勿共用給不需要的人。GitHub 為公開 repo，**只放程式**，不放任何資料或密碼。

## 七、部署與更新

步驟詳見 `部署說明.md`，摘要如下：
1. 在 dari25420001@gmail.com 建立試算表，開啟「擴充功能 → Apps Script」。
2. 貼上 `Code.gs` 與 `appsscript.json`，執行 `setup()`（建立分頁、排程與超級管理者帳號）。
3. 選擇性執行 `seedDemo()`（範例問卷與測試贈品）。
4. 部署為網頁應用程式，取得 `/exec` 網址，填入 `web/config.js` 後推送到 GitHub。
5. 到 https://script.google.com/home/usersettings 開啟「Google Apps Script API」，讓自動更新可以運作。

**更新流程**：Claude 修改程式 → 本機測試全部通過 → 推送 GitHub 並提高 VERSION → Claude 透過瀏覽器在 Apps Script 編輯器載入 GitHub 指定版本的 Code.gs、儲存，「管理部署作業 → 編輯 → 建立新版本 → 部署」，網址不變。（自動更新因 Apps Script 預設 Cloud 專案無法啟用 API 而停用。）

**測試與正式環境**：以兩份不同的試算表與兩個部署網址區隔。正式版的前台使用另一個 `config.js` 值。
